# Безопасность и ограничения 0.1.0

## Реализованные границы

- JSON не исполняется. Нет `source`, `eval`, shell-конкатенации аргументов команд.
- Root-команды передаются массивами аргументов с ограниченным окружением.
- UUID, ключи и URL подписок не передаются в argv процессов; QR получает данные
  через stdin, self-test — через защищённый временный файл.
- `status`, диагностика и журнал не выводят credentials. Сырые access/error logs
  nginx отключены, поскольку они могут содержать токены URL. Xray не пишет
  сетевые адреса пользователей в журналы.
- Источники и файлы проверяются на symlink, владельца, права и размеры.
- Один lock, `O_NOFOLLOW`, приватные временные каталоги, atomic replace и fsync.
- Xray работает отдельным непривилегированным пользователем. Systemd ограничивает
  файловую систему, устройства, capabilities и доступ к домашним каталогам.
- Nginx использует отдельные службу, конфигурацию и PID; чужой nginx не редактируется.
- Неподтверждённые запросы к токенам получают 404. Directory listing отсутствует.
- Удаление и reissue отзывают опубликованные endpoints; reissue меняет UUID.
- Xray запрещает проксирование к приватным адресам VPS и cloud metadata.
- Bootstrap закрепляет SHA-256 пакета; начальная версия Xray закреплена в исходниках.
- Обновления проверяются по SHA-256 из GitHub release metadata. Redirect загрузки
  не может понизить HTTPS до HTTP. Proxy-переменные окружения не наследуются.

Контрольная сумма подтверждает соответствие загруженному релизу, но сама по себе
не является независимой цифровой подписью. Доверенными остаются GitHub, аккаунты
издателей, TLS/CA, Ubuntu package repositories и владелец root-доступа.
Первый `curl | sudo bash` доверяет HTTPS-источнику bootstrap.

## Известные ограничения

- Требуется отдельный чистый VPS. Старая установка и её репозиторий не изменяются;
  автоматической миграции прежних shell-файлов нет.
- Проверки CI в контейнерах покрывают реальные Xray/nginx, Ubuntu/архитектуры и
  форматы. Reality target и адрес VLESS self-test в CI локальные, поэтому
  результат не зависит от сторонних сайтов. Они не заменяют пробную установку на VPS с systemd и публичным ACME.
- Внешняя доступность из РФ не проверена. Успешный self-test VPS этого не доказывает.
- Начальная установка без устройств не выполняет аутентифицированный VLESS-test;
  он обязателен при добавлении первого устройства.
- Автовыбор target — эвристика: разнообразный расширяемый каталог, измеренная
  доступность, задержка и совместимость первого ответа TLS с буфером REALITY
  (8192 байта). Проверки не доказывают пригодность сайта для любой сети
  или устойчивость к блокировкам. Автоматической привязки к ASN нет.
- Порты должны быть открыты в firewall ОС/хостинга. RUAVC не изменяет правила
  автоматически. Для Certbot standalone порт 80 должен оставаться свободным.
- Сам сервер слушает VLESS по IPv4. Российский geoip-источник не содержит полного
  набора российских IPv6; такие адреса могут идти через VPN. Локальные IPv6
  остаются в direct согласно профилю.
- Изменение конфигурации перезапускает Xray, поэтому активные соединения прерываются.
  Для больших списков устройств проверка каждого подключения занимает время.
- Приложение INCY обновляет профиль на клиенте по своему расписанию; сервер не
  может мгновенно изменить уже загруженный профиль.
- При откате неудачной операции клиент, успевший скачать кандидата, может потребовать
  повторного обновления подписки. Ручной rollback публикует новую ревизию.
- Пакеты Ubuntu, созданный системный пользователь и выданный ACME-сертификат могут
  остаться после неудачной первой установки. Работающие чужие службы не заменяются.
- Backups и поколения автоматически не удаляются в 0.1.0: это сохраняет возможности
  восстановления, но требует контроля свободного диска.
- Архивы backup не зашифрованы. Полный root-доступ позволяет читать все credentials.
- Наборы маршрутизации — сторонние данные; их полнота и классификация не гарантируются.
