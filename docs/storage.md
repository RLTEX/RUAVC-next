# Хранение и восстановление

RUAVC использует Python 3.10+ со стандартной библиотекой, распространяется одним
zipapp и запускает отдельные Xray и nginx через systemd. База данных, Docker
и внешняя панель управления для работы сервера не нужны.

## Пути

| Путь | Назначение и права |
|---|---|
| `/etc/ruavc/current` | Единственный указатель на активное поколение |
| `/etc/ruavc/generations/g-.../config.json` | Пользовательские настройки, root 0600 |
| `.../secrets.json` | Reality keys и shortId, root 0600 |
| `.../devices.json` | UUID/token устройств, root 0600 |
| `.../sites.json` | Пользовательские правила, root 0600 |
| `.../release.json` | Версии компонентов, digests, ревизия маршрутизации, root 0600 |
| `.../generated/xray.json` | Конфигурация Xray, root:ruavc-xray 0640 |
| `.../generated/nginx.conf` | Конфигурация отдельного nginx, 0644 |
| `.../web/` | Подписки и профили, root:www-data, каталоги 0750, файлы 0640 |
| `/opt/ruavc/code/<sha256>/ruavc.pyz` | Неизменяемая версия программы |
| `/opt/ruavc/xray/<sha256>/xray` | Неизменяемая версия Xray |
| `/var/lib/ruavc/datasets/<sha256>/` | Проверенные неизменяемые geo-файлы |
| `/var/lib/ruavc/pending.json` | Журнал незавершённой транзакции, 0600 |
| `/var/lib/ruavc/runtime.json` | Активное/предыдущее поколение и время проверки, 0600 |
| `/var/backups/ruavc/` | Защищённые backup-указатели и полные архивы, 0700 |
| `/var/log/ruavc/` | Маскированный журнал, 0700/0600, ротация по размеру |
| `/run/ruavc/` | Временные self-test конфиги, 0700/0600 |

Каталоги поколений имеют 0711: службе доступен её заранее известный файл,
но список секретных документов и содержимое недоступны. Публичный nginx
обслуживает только точные формы URL подписок, авторизованных профилей и geo-файлов.
Файлы конфигурации не раздаются по HTTP.

## Транзакция

1. Общая блокировка исключает параллельные изменения и гонки с таймером.
2. В памяти собирается кандидат; проверяются JSON, ключи, sites и geo-файлы.
3. Создаётся отдельное поколение с производными конфигами и подписками.
4. Выполняются `xray run -test` для сервера и маршрутизации, `nginx -t`.
5. Сохраняются предыдущая версия и durable journal с `fsync`.
6. `current` переключается атомарным переименованием ссылки.
7. Службы перезапускаются с конкретными путями нового поколения.
8. Проверяются process/config, порты, маскировка, HTTPS, точное содержимое
   подписок и geo-файлов, VLESS для каждого устройства, недоступность старых URL.
9. Фиксируется runtime state, журнал удаляется после успешной проверки.

При исключении, включая Ctrl+C, восстанавливается предыдущий указатель и службы.
При потере питания журнал читается `ruavc-recover.service` до запуска VPN и HTTPS.
Если восстановлению мешает отдельная неисправность, журнал остаётся, команда
возвращает код `4`; ошибка не маскируется сообщением об успехе.

Атомарность относится к файлам состояния. Перезапуск Xray разрывает существующие
соединения; распределённой транзакции с уже импортированными клиентами нет.
Ручной rollback/restore создаёт новую возрастающую ревизию INCY-профиля.

## Backup

Каждое изменение сохраняет предыдущее поколение. Полный архив создаётся через
`backup create`: исходные документы, программа, Xray, geo-файлы и manifest SHA-256.
Restore не распаковывает произвольные пути: допускается только фиксированный
набор обычных файлов, с ограничением размера и проверкой контрольных сумм.
Копия применяется через тот же механизм validation/restart/self-test/rollback.

Архив не зашифрован; содержит доступы всех устройств. Для переноса требуется
защищённое хранилище. TLS-сертификаты Let's Encrypt не входят в архив: они
управляются Certbot и перед применением восстанавливаются для нужного домена.

В 0.1.0 восстановление выполняется на установленном RUAVC: архив располагается
в `/var/backups/ruavc/`, затем `backup restore ИМЯ`. При переносе на другой адрес
потребуется настройка домена и `server.address`; автоматического переноса DNS нет.
Восстановление старого backup может вернуть ранее отозванные credentials.

## Раздельные обновления

RUAVC и Xray загружаются по конкретной версии с проверкой SHA-256; новая программа
проверяет схему и применяет миграции до переключения. У версии 0.1.0 первая
публичная схема `1`: неизвестные предыдущие и будущие схемы отклоняются.
Импорт shell-конфигурации прежнего проекта не выполняется.

Наборы российских ресурсов загружаются с закреплённого Git commit ветки `release`.
Файл и его контрольная сумма относятся к одному commit. Проверяются protobuf,
обязательные категории и корректность правил в Xray. Полный набор переименовывается
атомарно; URL включает digest, поэтому INCY не смешивает разные версии файлов.
При ошибке сети старые данные и VPN сохраняются.
